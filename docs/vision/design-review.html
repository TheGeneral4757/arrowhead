Recommendation: Tauri 2 with a web front end

The engine runs on its own Rust threads, so webview hiccups cannot touch press timing. The UI in this review is web, and Hallmark designs for the web, so these mockups carry straight over. If webkit2gtk becomes painful on Linux, the same front end moves to a local server in a browser with no rewrite. The click-through overlay is a separate small process (layer-shell on Wayland, a layered topmost window on Windows), because Tauri windows cannot do per-region click-through.

Front end: React and TypeScript lets v2's pages be read across. Svelte 5 is lighter. Both are fine.

Research: risks

Sober FPS
Open Sober issue 2027: 16 fps while focused on KDE Plasma 6 Wayland on CachyOS, your exact setup. Test before anything else
Sober input
Open issues with no keyboard input after launch (1959, 1940, 973)
Region capture
Neither KDE nor Hyprland portals crop to a region; arrowhead crops on the CPU, as v2 does
Overlay
Whether a layer-shell overlay shows above a fullscreen game on KWin needs a spike
Windows
Whether Roblox's anti-cheat on Windows blocks synthetic input or capture is unknown

Research: worth taking

Prior art
Existing Funky Friday bots sample fixed pixels at one resolution, with no holds and no humanizing. arrowhead's design already avoids their failures
Self-check
Score arrowhead's own output with unstable rate (osu!'s spread measure, via circleguard) so a preset never reads as uniform jitter
Text
Template matching for digits on the scan thread; ocrs only off the hot path
Focus guard
KWin script on KDE, IPC socket on Hyprland, foreground window on Windows
Input fallback
libei through the RemoteDesktop portal if uinput is not writable
Latency test
A test window that flips a pixel on key press, timed through the same capture path
